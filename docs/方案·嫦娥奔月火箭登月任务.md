# 方案：全景模式下「嫦娥奔月 · 火箭发射—登月」全程演示任务

> **状态：设计提案（待 DeepSeek V4-pro 审查后实施）**
> 目标：在全景（orbit-view）模式下，由老师**手动点按钮**触发一次完整的"地球发射火箭 → 升空 → 分级脱离 → 嫦娥进入太空轨道 → 地月转移 → 进入月球环绕轨道绕行多圈 → 着陆月球"，着陆后弹"登录月球成功"，点确定自动关闭模式。

---

## 1. 需求与交互（必须满足）
1. 全景模式下新增一个**手动触发按钮**（不自动播放），如 `🚀 嫦娥奔月`。
2. 点击后进入"奔月模式"，播放完整阶段序列。
3. 全程可见：地面点火、升空、**火箭分级脱离**、嫦娥进入**地球环绕轨道**、**地月转移**、进入**月球环绕轨道并绕行多圈**、**着陆月球**。
4. 着陆后弹出**「登录月球成功」**弹窗；老师**点"确定"→ 该模式自动关闭**（火箭/嫦娥隐藏、恢复全景正常状态）。
5. 模式中应提供**取消/跳过**（避免演示卡死），以及受控的**播放速度**（默认让 3 天行程压缩到约 25-35 秒，可调）。

## 2. 架构与模块划分
- 新增 `src/modules/lunar-mission.js`：**`LunarMission` 控制器**，是一个纯"任务状态机 + 弹道计算 + 场景对象管理"的**独立控制器**（不是教学模块，不占 Tab；挂在全景场景里）。
- 它向全景场景（`system.scene`）添加**火箭模型、嫦娥探测器模型、地月轨迹线、羽流特效**，并驱动其移动；不接管整屏（保留全景的星场/行星/标签）。
- 由 `main.js`/`mobile-main.js` 在 `orbit-view` 激活时注入；按钮点击 → `lunarMission.start()`。
- 弹窗复用现有 `openModal/closeModal`（`ui/help.js`）。

> 关键决策：**它不是一个独立的 `module-switch` 模块**，而是叠加在"全景"之上的一段"叙事"。这样不新增 Tab、不破坏已有的 6 模块结构，切模块时自动取消/隐藏任务。

## 3. 场景与尺度（教学示意尺度）
- 复用全景的教学尺度：
  - 地球视觉半径 `R_E` ≈ 0.0511 AU（×1200 放大）；地位于真实日心位置。
  - 月球视觉半径 ≈ 0.02 AU；月球采用**真实星历方向**（`astro.moonGeoScene`），距离取**示意值**（见 4.3，保证教学可见）。
  - 地球—月球示意距离 `D_EM`（提议 ≈ 0.55 AU，明显大于教书半径且能同屏看清轨道）。
- 任务全程在"地球质心系（地球段）/月球质心系（月球段）"之间用**拼接圆锥（patched-conic）**切换，角度、视觉连续。
- 轨迹几何**符合两体开普勒轨道**（真近点角参数化，近日快、远日慢），数值可被复核。

## 4. 阶段状态机（核心）
定义枚举 `Phase`：`IDLE → LAUNCH → ASCENT → STAGE_SEP → EARTH_ORBIT → TLI → TRANSFER → LOI → LUNAR_ORBIT → DESCENT → LANDED → (成功弹窗 → DONE)`

### 4.1 各阶段要点
| 阶段 | 时长(示) | 动作 | 视觉 |
|---|---|---|---|
| LAUNCH | ~1s | 点火，地面烟/羽流 | 火箭立于发射台，喷焰+震颤 |
| ASCENT | ~4s | 垂直/向东加速升空 | 尾焰拉长，穿云出大气 |
| STAGE_SEP | ~1.5s | **助推器/一二级分离** | 侧向分离的小型助推器翻滚坠落（淡出） |
| EARTH_ORBIT | ~3s | 上面级入 **地球停泊轨道**(圆) | 绕地球一圈 |
| TLI | ~1.5s | 近地点点火加速（借力） | 轨迹由圆变椭圆，尾焰 |
| TRANSFER | ~8s | 沿 **霍曼转移椭圆** 滑行到月球 | 地月转移弧线，可显示轨迹线 |
| LOI | ~1.5s | 月球制动，**月球停泊轨道**(圆) | 轨迹收拢为绕月圆 |
| LUNAR_ORBIT | ~8s | **绕月 3 圈**（多圈） | 明显绕月球多圈 |
| DESCENT | ~5s | 减速垂直下降 | 月面渐近，着陆腿/反推焰 |
| LANDED | 定格 | 着陆成功 | 月面停稳，弹出成功弹窗 |

### 4.2 状态机约束
- `Phase` 单向推进，`LunarMission.setState()` 统一管理；每阶段有 `enter/update(t)/exit`。
- **任一时刻可 `cancel()`**：清空任务对象、复位弹窗、恢复相机/UI，不残留。
- **速度 `rate`**：整段用 `Config` 里的"任务加速系数"，默认 `k`（把真实 3 天 ≈ 60h 压缩到 ~30s）。老师可暂停/调速（复用时钟倍速，或用独立任务速率）。

### 4.3 弹道（两体开普勒，拼接圆锥）
- **地球停泊轨道**：圆，半径 `r_park`（示 = `R_E*1.25`，略高于放大的地球表面）。
- **霍曼转移椭圆**：近地点 `r_park`，远地点 `r_moon = D_EM`；半长轴 `a=(r_park+r_moon)/2`，离心率 `e=(r_moon-r_park)/(r_moon+r_park)`。用**真近点角 ν** 参数化：`r=a(1-e²)/(1+e·cosν)`；对 ν 积分求"沿弧长匀速/按时间"前进（用简化时间→偏近点角 `E` 近似，保证近日快、远日慢，且总时长可控）。
- **月球段切换**：到达 `r≈r_moon` 且靠近月球时，切换为月球质心系：
  - **月球停泊轨道**：圆，半径 `r_lunar`（示 = 月面示意半径 ×1.5，如 `0.03 AU`）。
  - **绕行多圈**：θ 从 0 → 3×2π。
- **着陆**：从月球停泊轨道**径向减速下降**（不模拟真实动力反推/悬停，用平滑缓动让"软着陆"观感成立），`r` 从 `r_lunar` → 月面半径。落点角度取绕行终点方向。
- 数值表（示意尺度，供校验）：
  - `R_E=0.0511`, `R_Moon=0.02`, `D_EM=0.55`, `r_park=0.064`, `r_lunar=0.028`。
  - 上述为 AU；如 V4-pro 建议改动，仅改常量即可。

### 4.4 真实月球方向
- 月球方向用 `astro.moonGeoScene(jd)` 实时方位（但不改变其"示意距离"，因为 `D_EM` 是教学值）。任务期间**冻结时钟**（避免月球位置跳动导致轨迹错位）；或任务全程用**开始时刻的月球方向**，避免漂移。

## 5. 视觉与模型
- **火箭（多级）**：`RocketModel`——整流罩/上面级/芯级/助推器；分级时把已分离组件独立成节点，做侧向分离+翻滚+淡出。
- **嫦娥探测器**：`ChangEModel`——着陆器（四条着陆腿）+ 轨道器/服务舱；进入月球段后可"抛弃/隐藏"服务舱只剩着陆器（体现登月）。
- **羽流/尾焰**：锥形发光体 + 粒子喷焰（`Points` 或 additive 圆锥），点火/分级/制动时可见；**不使用 THREE.Sprite**（本工程禁用）。
- **轨迹线**：把地球停泊圆、转移椭圆、月球停泊圆各自生成的 `Line`，仅任务期间可见；可加"当前途经点"高亮。
- **HUD 覆盖层**：任务期间左上角显示 `阶段 · 高度 · 速度`（DOM，`position:absolute`），复用现有 `.viewlabel` 样式。

## 6. 相机（跟随式电影镜头）
- 任务期间用一套**自动跟随相机**（独立于用户 OrbitControls）：
  - 近地阶段：镜头从"发射台"拉远到"地球＋火箭"。
  - 转移阶段：拉远到"地球—月球"同框，跟住嫦娥。
  - 月球段：跟到月球，绕行时缓慢环绕。
- 在 `enter()` 时**临时停用**全景 `cameraRig.controls`（`enabled=false`），任务结束/取消恢复（参照卫星模块做法）。
- 提供"🔭 自由视角/自动跟随"切换（可选加分项）。

## 7. 生命周期与错误处理
- `start()`：构建任务对象、拉起相机、`bus.emit('mission.start')`。
- `cancel()` / `stop()`：可从"取消"按钮或成功弹窗"确定"触发。
- **成功弹窗**：`openModal('mission-success', '🌕 登录月球成功')` → 点"确定" → `finish()`：
  - 隐藏火箭/嫦娥/轨迹/特效，`system.scene` 复原；恢复全景相机、标签、指针事件；`bus.emit('mission.end')`。
- 若任务中切到其他模块（`module.switch`），`main.js` 调 `lunarMission.cancel()` 兜底（避免残留在别的模块里）。
- 全程不抛未捕获异常：`update` 包 try/catch，出错即 `cancel()`。

## 8. 与全景整合（避免破坏现有）
- 按钮：加在 `#view-tools`（右侧工具条）为 `🚀 嫦娥奔月`；`pointer-events:auto`。仅在 `orbit-view` 且任务空闲时可用；任务中变"⏹ 停止任务"。
- 任务对象挂在 `system.scene`（与行星同层，不进入星球 `bodyGroups`，避免被 pick/聚焦）。
- 不修改 `switchModule`/教学模块；只在 `orbit-view` 激活时注入与解绑；`setOverviewUI` 保持不变。
- 任务期间隐藏行星菜单/比例/月地等按钮（避免误触），仅保留"停止任务"。

## 9. 测试与验收
- 新增 `scripts/verify-lunar.mjs`：无头浏览器点按钮 → 逐阶段轮询 `lunarMission.phase`，断言走完 `LANDED`；检查成功弹窗出现、点确定后 `phase===DONE` 且场景恢复、无 pageerror。
- 回归：`npm run test:all`（单测12 + 桌面e2e48 + 手机自检6 tab）保持全绿；`check-switch` 无黑边。
- 验收点：阶段顺序正确、分级可见、绕月≥3圈、着陆后弹窗、点确定自动关闭、取消可随时退出、切模块自动取消。

## 10. 分阶段实施步骤
1. 常量表 + `LunarMission` 状态机骨架（可空转不渲染）。
2. 火箭/嫦娥模型 + 羽流 + 轨迹线。
3. 弹道引擎（停泊圆 + 霍曼转移 + 月球圆 + 着陆下降），纯函数可测。
4. 相机跟随 + HUD + 成功/取消弹窗。
5. 接线到 `main.js`/`mobile-main.js` + 按钮 + `cancel` 兜底。
6. 新增 `verify-lunar.mjs` + 回归测试；双端截图目检。

## 11. 风险与待确认（请 V4-pro 重点核对）
1. **尺度/轨迹**：教学示意尺度 + 拼接圆锥是否够"物理上说得通"？`D_EM=0.55`、`r_park`、`r_lunar` 取值是否合适？
2. **霍曼转移的"时间→真近点角"**：近地点快/远地点慢的观感用偏近点角近似是否可接受，还是要严格求解开普勒方程？
3. **月球真实方向 vs 示意图距离**：方向用实时、距离用示意，是否会造成"轨迹终点≠月球中心"的视觉偏差？建议任务期冻结月球方向。
4. **"多圈→着陆"**：绕月 3 圈后直接径向着陆，是否要加"变轨圆→着陆"的过渡（环月轨道高度降低）？
5. **火箭分级**：简化分离（助推器翻滚坠落淡出）是否符合预期；是否需要整流罩抛罩。
6. **性能**：羽流粒子 + 轨迹 + 相机在老旧机型是否流畅（已有低档降级，任务期是否要自动降档）。
7. **交互边界**：任务中是否允许点星球/切比例？建议禁用以免错乱；成功/取消后完全恢复。

## 12. 结论 / 待审查点
本方案把"嫦娥奔月"做成**全景之上的叙事演示**：物理用两体开普勒（霍曼转移+拼接圆锥），视觉给足（多级火箭、分级、嫦娥建模、羽流、轨迹、HUD），交互满足"手动触发→全程展示→着陆成功弹窗→确定自动关闭"，并保证不破坏现有 6 模块与测试。**若 V4-pro 认可尺度和弹道取舍，即可按第 10 节实施。**

# 附：方案审核意见（2026-09-04 · 对照现有代码逐条核对）

> 审核方式：通读方案 + 对照 `src/modules/orbit-view.js`、`src/config.js`（MOON_ORBIT_SCHEMATIC 等）、`src/main.js`（空闲省电/相机/切换）的现有实现逐条核对。

## A. 必须修正的问题（否则实现出来必然出错）

### A-1【严重·尺度冲突】`D_EM=0.55` 与现有月地示意距离不符
- 现状：全景里月球显示在 `MOON_ORBIT_SCHEMATIC = 0.16 AU`（`config.js`）。方案却写 `D_EM=0.55`。
- 后果：转移椭圆远地点 0.55，而屏幕上月球在 0.16 → **嫦娥会飞到一个没有月球的地方**，"进入月球轨道"对不上。
- **修正：`D_EM = 0.16`（直接沿用现有示意距离），停泊半径 `r_park=0.064`、月球停泊 `r_lunar=0.028` 相应保留**；转移椭圆：`a=(0.064+0.16)/2=0.112`、`e=(0.16-0.064)/(0.16+0.064)≈0.429`（有效椭圆）。

### A-2【严重·几何】转移椭圆"长轴必须指向月球"
- 方案只写"月球用真实方向"，未说明**转移椭圆的近地点—远地点连线必须与"地球→月球"方向共线**，否则远地点不会落在月球位置上。
- **修正：任务开始时冻结"地球→月球"方向（冻结时钟后自然固定），转移椭圆长轴沿该方向放置；远地点=月球显示位置。** 这同时解决"轨迹终点≠月球中心"的视觉偏差。

### A-3【严重·状态一致性】任务期必须冻结模拟时钟
- 若不冻结，月球（真实星历）持续移动，A-2 的对齐会逐渐失效；行星也在动，干扰演示。
- **修正：`mission.start()` 时保存并暂停时钟（`clock.running=false`，记录原倍速）；`finish()/cancel()` 恢复。** 任务动画由任务自己的 `k` 速率驱动，不依赖时钟。

## B. 必要补充（不改会出体验/正确性瑕疵）

- **B-1 任务期强制月球"示意"模式**：若用户此前把月地切到"真实/隐藏"，登月演示会失去目标。开始任务时 `orbitView.setMoonMode('schematic')`，结束恢复原状态。
- **B-2 开普勒方程建议直接数值解**：`M` 线性推进，用牛顿迭代解 `E - e·sinE = M`（约 5 行代码），既严格又便宜；取消方案里"偏近点角近似"的含糊表述。
- **B-3 任务期禁用空闲省电**：`main.js` 的空闲跳过（暂停+相机静止 600ms 不渲染）可能误判任务静止。把 idle 条件加 `&& !mission.active`（或任务相机始终微动）。同样适用于手机端循环。
- **B-4 手机端按钮位置**：手机端没有 `#view-tools` 工具条。需要给手机版加一个浮动"🚀 嫦娥奔月"按钮（如 `m-top` 或右下 FAB），并保证任务相机在竖屏下取景（地月同框在竖屏需拉远）。
- **B-5 发射点取"月面对向"**：发射台设在**正对月球的那一侧**，升空方向与后续转移方向大致一致，视觉最自然；否则会出现"先绕一圈再奔月"的怪感。
- **B-6 相机复原**：`finish()/cancel()` 后不仅要恢复 controls，还要把相机**复位到一个合理机位**（如 `cameraRig.setPreset('earthMoon')` 或回全景机位），否则停在奇怪的镜头位置。
- **B-7（可选）绕月→着陆加"降轨"**：绕 3 圈后加约 2 秒"环月轨道降低 + 动力下降"，比直接径向着陆更自然；实现仍是缓动下降，成本低。

## C. 确认可行、可照做的部分
- "全景之上叙事、不加 Tab"的定位正确，与 6 模块结构不冲突。
- 阶段状态机（LAUNCH→…→LANDED→成功弹窗→DONE）、手动触发按钮、成功弹窗"确定后自动关闭"、随时 cancel、切模块自动取消——设计完整。
- 拼接圆锥（地球质心系/月球质心系切换）+ 两体开普勒 + 真实月球方向（冻结后）——物理上说得通。
- 火箭/嫦娥建模、羽流（不用 Sprite）、轨迹线、HUD、跟随相机——实现路径清晰。
- 测试方案（`verify-lunar.mjs` 逐阶段断言 + 全量回归）合理。
