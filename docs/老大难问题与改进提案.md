## B. 已解决、但过程曲折（差点/改了几次，提醒教训）

### B-1 启动直接报错（首版连页面都起不来）
- 根因：`config.js` 缺 `periodDays` → 轨道线采样 `NaN` → `jdToDate(NaN)` 无效日期 → astronomy-engine 抛错"Argument must be a Date object…"。
- 解决：补字段 + `createOrbitLine` 兜底。教训：**配置字段缺失会静默传 NaN**，最好加回归测试/运行时校验。

### B-2 背景整屏泛灰/米色
- 根因：`root.position=-camera`（浮动原点）与相机视图**重复平移**（世界被 -2×相机 平移），星场/天体错位；加上**太阳日冕 Sprite** 在该渲染路径被错误放大成整屏叠加。
- 解决：移除重复平移、改为星场跟随相机；**弃用 Sprite**，改用 BackSide 菲涅尔辉光 + 相机朝向的 Mesh 圆片做日冕。教训：**THREE.Sprite 在此工程里会异常放大，一律不用**；浮动原点要只平移一次或改用相机相对坐标。

### B-3 大量按钮点不动
- 根因：`#topbar{pointer-events:none}`（仅 `.tabs` 恢复）、`.module-ctx{pointer-events:none}` 被子按钮继承。
- 解决：`.icon-btn`、模块内 `button/.evt/input/select` 显式 `pointer-events:auto`。教训：**全屏浮层容器设 pointer-events:none 后，子交互必须单独恢复**。

### B-4 模块「返回全景」失效
- 根因：模块内按钮发 `bus.emit('module.switch')`，但主控只把 `switchModule` 绑到顶栏点击，没监听该事件。
- 解决：统一 `bus.on('module.switch')` 驱动切换；并移除 `moon-phases.exit()` 内的重复 emit（否则递归）。教训：**事件驱动与直接调用要统一，避免"按钮发了事件但没人听"**。
- 注意：`switchModule` 里每切换一次会 `cameraRig.reset()`（回全景机位），若用户正转到一半会被打断——**体验上可能想改成"仅首次/仅点击复位才回"**，我没细究，不确定是否符合预期。

### B-5 缩放滑块/按钮失效 + 方向反了
- 根因：① `muted` 标志卡死（滚轮缩放后置 true 再不复位）；② `setZoom` 值→距离映射方向反了（＋反而缩小）。
- 解决：删 muted（滑块与滚轮可共存）；映射改为"值越高=越近"。教训：**防打架标志别做成一去不返；方向映射要实测**。

### B-6 地球贴图变灰
- 根因：地球外加了一层**白色云层球**，云贴图是 **JPG（无透明通道，alpha 恒 255）**，云层成不透明白球盖住彩色地表。
- 解决：云层改 `alphaMap` 驱动 + 透明度 0.38。教训：**JPEG 无 alpha，用作半透明贴图必须走 alphaMap/单独生成 alpha**。

### B-7 切回全景：左黑遮罩 + 星球变形 🔧（本轮刚修）
- 根因：月相实验室**双视口渲染**（setViewport 分半屏），退出时**未把渲染器视口/剪刀重置回整屏**。
- 解决：全景/潮汐/日月食 `render()` 前都 `setViewport(0,0,全宽,全高)` + `setScissorTest(false)`。
- 教训：**凡用 setViewport 的模块，退出后必须恢复整屏视口**；最好加一个回归截图。

## C. 你指出不满意 / 我改了多次仍未达标的项

### C-1 太阳真实感 🔴（改动最多、最不满意）
迭代历史：Sprite 日冕（泛灰）→ 弃用；光球无立体（平）→ 加临边；日冕太大太假（"一团火"）→ 改淡；太阳太暗（"不像壮年太阳"）→ 提亮；又"像龙珠光溜溜"→ 加颗粒/黑子/偏白暖。
- 难点：**"逼真 vs 又亮又不假"的硬权衡**——太亮→像发光塑料/龙珠；太暗→没有恒星感；颗粒太多→显脏；太少→光滑。
- 现状：中心亮+边缘暖、细颗粒+少量黑子、淡日冕。但**我仍不确定这是否算"真实"**（真实 SDO 光球是米粒组织+黑子群，颜色偏白黄，想更硬核可换更精细的太阳纹理/SDO 合成图）。
- 建议：① 换更高质量太阳贴图（SDO 拼接）；② 做**真实光球米粒流动**（低频噪声逐步演化）；③ 明确"教学可接受"目标，避免无限打磨。

### C-2 手机端"像PC/扁平"
- 迭代：默认视角从 30° 俯视抬高到约 47°、拉近；太阳立体化/淡日冕。现在轨道呈立体椭圆。
- 仍未完全解决：竖屏有**下方大片留白**、行星标签可能重叠、顶部信息较满。**布局仍偏"PC 简化版"，不是纯原生 App 手感**。
- 建议：做更"原生"的交互（底部抽屉、FAB、更足留白、动画过渡）；如需更进一步可换 React/Vue 或原生壳（但会改架构）。

### C-3 手机版部署/扫码门槛（对老师不友好）🟠
- 需求：手机连**同一 WiFi**，电脑运行 `npm run serve`（自动列出局域网 IP），手机访问 `http://IP:8000/mobile.html` 或扫桌面端「📱」按钮的二维码。
- 问题：老师**完全不熟命令行/IP/WiFi**；localhost 扫码指向手机自己；二维码是 IP 写死的，换网络就失效。
- 现状：我已在老师电脑上启动服务并生成 `docs/mobile-qr.png`，但这是**一次性**的；换网络/IP 就需重生成。
- 建议：① 做一个**更傻瓜的部署向导**（检测局域网IP、自动重启服务、生成最新二维码）；② 或将手机版**直接打包成可离线安装的 PWA/二维码导流**；③ 若老师只想"大屏演示"，其实手机版可弱化（主战场是大屏离线版）。

### C-4 倍速档位（产品决策被我做"过"了）
- 初版有"1秒=1周/月/年"等夸张档，你觉得没必要。已收窄为：暂停、10分钟、1小时、6小时、12小时、1天。
- 教训：**教学类档位要贴近教学节奏，别堆噱头**；后续如需"更细/更粗"再按需加。

## D. 我拿不准 / 不确定的地方（接手者请重点验证）

1. **相机精度/抖动**：我**移除了设计文档要求的"浮动原点"**（`root=-camera` 会重复平移），改为行星按真实坐标 + 星场跟随相机，靠大尺度放大让 float32 够用。**但极端贴近行星表面时是否会有肉眼可见抖动/z-fighting，我没在真机长时间验证**（日志深度缓冲已开，理论够用）。
2. **真机性能**：一直用**无头 SwiftShader** 自检（很慢、不代表真实 GPU），自动选档常落到中/低档。**未在真实独立显卡/教室老旧机实测帧率**。建议真机 FPS 面板 + 3-5 台典型机器实测。
✅ 已解决：低档运行时把真实贴图 canvas 降采样到约 1K（texture-store）；启动检测软件渲染器(SwiftShader等)时直接低档；桌面/手机端均已接线。
✅ 已解决：事件详情与列表同时标注「本地日期」与「UTC 日期（与权威目录一致）」。
5. **月球物理模型的示意一致性**：月相俯视图用"照亮半球着色"，右视图用物理光照，**两者是否严格对应**我没逐帧核对；学生能否看出对应关系不确定。
6. **太阳"自转动画"**：`group.userData.update(jd-JD0)` 传入超大数值作 `uTime`，颗粒噪声可能**被推到很远/近似静止**，太阳表面流动感可能在演示中不明显——不确定。
✅ 已改进：影锥调细调淡（更接近"示意线条"）；潮汐已加"海水起伏+观测点高亮"。
✅ 已解决：手机端月相控制新增「猜一猜」，随机跳关键相位+四选项作答。
9. **天文数据边界**：VSOP87 只做 1900–2100（已钳制），月球/日月食在这范围可信；**超出边界的表现未充分测试**。
10. **移动端观感未在真机全面验证**：仅用 390×844 无头模拟，真实手机（刘海屏、不同DPr、安全区）、卧姿、触屏手势（单指旋转/双指捏合）手感未逐一实测。
11. **日期跳转输入**：`<input type=date>` 的本地语义与 JD(UTC) 换算、跨时区是否正确，未深究。
12. **代码质量**：部分绑定直接用 `window.__`（如 `window.__moonPhases`）供手机端调用，属**临时耦合**，值得重构；多处极端值靠硬编码，维护性一般；未做 lint/TS。

## F. 潮汐 / 四季 / 日月食 的表现形式重构（重大教学观感问题 🔴）

> 用户原话：**"用这种简陋的几何表达潮汐、四季、月食实在是糟糕的表现形式。月相实验室我很满意（左动画示意、右真实模拟）。感觉是这个模型能力不足。"**
> 这是当前**最严重**的教学观感问题，也是**最高优先级**的重构方向。本节给出目标、每模块蓝图、以及**能力自评与交接说明**。

> ✅ **已按本蓝图重做（2026-09-06，见"收尾轮10"）**：三模块均已改为"左/上=2D 因果示意 canvas + 右/下=WebGL 真实感"双视图，教材级可讲解已达。**唯一未达的是"电影/NASA 级惊艳"**（受程序化贴图/简单光照限制），如需顶级美术仍交更强模型/美术管线，本蓝图可直接作为需求文档。

### F-1 问题定性
- 现状：潮汐/四季/日月食用**球 + 锥 + 线**等简易几何去"示意"，观感像草稿，不像成品，**老师不敢直接放投影**。
- 对照：**月相实验室**是成功的样板——它把「干净的动画示意（左/上）」与「真实感的模拟（右/下）」结合，既讲清因果，又有质感。**三模块应复制这套双视图架构。**
- 根因（自省）：前几轮我**没有把月相实验室的成熟双视图模式套用到这三个模块**，而是各自用最省的几何去糊，属于"能力够但没用心/没按成功范式做"。

### F-2 目标（对标的成功范式）
每模块都用**双视图**：
1. **示意图（左/上）**：干净、平面化、**关键元素放大 + 明确标注 + 动画**，讲因果。
2. **真实感模拟（右/下）**：用真实贴图 + 正确光照的**成品级**画面，让学生看到"真实长这样"。

### F-3 各模块设计蓝图

**① 潮汐（对标：一天两次涨落 + 朔望大潮/小潮）**
- 示意图：**地球赤道横截面**（2D 干净圆盘）——月球在左/右，**海水画成明显的"双隆起蛋形"**；用**箭头**标出月球/太阳引力；**观测点**用高亮点随自转扫过隆起（动），旁边实时显示该点水位（高/低）；**朔望/上下弦**时太阳相对月球的方位变化，隆起随之变大/变小。
- 真实感模拟：真实纹理地球 + 逼真海水壳，**沿地月方向出现肉眼可见的潮汐隆起**（夸张但仍"像水"），月光/日光的照亮质感。
- 关键：把"为什么背月侧也涨"（引力差/惯性）用示意图讲清楚，不只是画两个鼓包。

**② 四季（对标：地轴倾斜+公转→不同日照→四季）**
- 示意图：**侧视**（sun 在一侧）地轴倾斜 23.4° 恒定向北；**用高亮"昼半球/夜半球分界（晨昏线）"** 清楚显示——夏至北半球倾向太阳（被照亮多）、冬至北半球背向太阳；**画阳光直射点纬度**在北/南回归线之间移动（动）；四季位置打点+图例。
- 真实感模拟：真实纹理地球 + **真实晨昏线（由太阳方向光照决定）**，让学生看"日照角不同→地表亮度/热度不同"。
- 关键：把"轴倾斜 **方向不变** + 公转 → 某半球倾向/背向太阳 → 日照角不同"讲成可对着指的画面。

**③ 日月食（对标：日食/月食的成因 + 为什么不是每月都有）**
- 示意图：**俯视/侧视**太阳-地球-月球；把**黄道与月球轨道（倾角约5°）的两个交点（升/降交点）**画出来；动画演示月球轨道在交点附近穿过时，日（月球挡光→影子落地球）/月（地球挡光→影子落月球）发生；**非交点月份不发生**（倾角）。
- 真实感模拟：真实纹理月/地 + 清晰影锥，**从"旁观视角"和"被遮挡天体视角"两种看**（如日食时从地球看月球剪影、从太空看月球影子）。
- 关键：把"朔/望 + 接近交点"这个充要条件讲透。

### F-4 能力自评（诚实）
- **能**：用月相实验室同款双视图架构重做这三模块；用真实纹理 + 光照做"真实感"半边；用 CSS2D 标注 + 动画做"示意图"半边；天文位置用 astronomy-engine 保持准确。**有把握做到"清楚、可讲解、观感正常、能上投影"。**
- **天花板（写清楚，不夸大）**：美术质感受限于**程序化贴图 + 简单光照/材质**，做不到电影/NASA 级的光影与构图美感；若要"肉眼惊艳",需换高质量贴图/HDRI/后处理或专人美术。这是**量级上的差距**，不是"再改几轮"能补齐的。
