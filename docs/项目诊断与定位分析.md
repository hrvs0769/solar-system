# 项目诊断：定位与下一步

> 日期：2026-09-12
> 背景：项目已转向幼儿园课堂免费演示，完成三批次迭代（历史缺陷修复 / 儿童模式 / 稳健性收尾）后的一次定位复盘。
>
> **结论先行：这个项目的核心问题不是技术问题，是产品定位分裂——用一套面向中学的天文教学工具，去满足幼儿园课堂的需求。**

---

## 一、最根本的问题：内容与目标用户不匹配

项目的原始定位在《太阳系教学系统·详细设计文档》中写得很清楚：VSOP87 行星位置、开普勒面积定律、霍曼转移轨道、食相判定。**这套东西的目标受众是初中以上。**

幼儿园的实际情况是：儿童模式做的是放大字号、隐藏控件、换白话文案。

**但内容没变。** 小朋友看到的还是那个太阳系全景——8 颗行星、椭圆轨道、真实开普勒运动。一个 4 岁小孩看这个，认知负荷和看一堵花花绿绿的墙差不多。

**这不是儿童模式能解决的，是内容本身不对。**

## 二、幼儿园天文课实际只讲四件事

1. 白天和黑夜（太阳出来是白天，落下是黑夜）
2. 太阳和月亮的样子（圆的、亮的）
3. 月亮会变（弯弯的像小船，圆圆的像盘子）
4. 星星（很多很多、会眨眼）

不教：行星、轨道、公转周期、日食月食成因、火箭发射原理。

对照现有模块：

| 模块 | 对幼儿园是否有用 |
|---|---|
| 月相实验室 | **命中**（"月亮会变样子"） |
| 嫦娥奔月 | 半命中（当故事看，不是当航天课） |
| 全景行星运转 | 无 |
| 日月食 | 无 |
| 卫星 | 无 |

**"就月相满意"不是因为月相做得最好，而是只有它对得上目标用户。** 潮汐四季被判"不满意"，本质是它们离幼儿园更远。

## 三、儿童模式是自我安慰

它隐含的前提是"内容没问题，只是形式对小孩不友好"。**这个前提是错的。**

如果目标真是幼儿园，正确做法不是加开关，是**砍掉全景、卫星、日月食，只留月相，再补一个"白天黑夜"**。

砍掉的成本为零——因为小朋友本来就不看。

## 四、比内容更紧急的问题：老师不知道怎么用

打开软件，老师面对 12 个顶栏按钮、5 个模块、40+ 可交互元素。她的问题不是"这个按钮干什么"，而是：

> **"这节课我按什么顺序点？每步说什么？"**

现有的引导流程教的是**怎么操作软件**（旋转、缩放、全屏），不是**怎么上一节课**。

**该做的是「课堂模式」**：选年龄段 → 软件按预设脚本一步步走 → 每步屏幕上有大字讲解词，老师照着念 → 老师只按"下一步"。

也就是**从「工具箱」变成「课件」**。

**嫦娥奔月是全项目唯一符合这个形态的东西**——它自己会走、有解说、老师只需点开始。这是项目最该有的样子，但只做了一个。

## 五、现在最该做的事：停止改代码

项目完成度已经很高，但**所有验证都是自动化测试，没有一个真人老师、真人小朋友碰过它**。

继续改就是在猜。老师用一次拿到的信息，比再改三个月都多。

具体做法：
- 把 `dist-offline/` 拷给老师
- 让她按平时的习惯用，你在旁边看
- 记录她第一分钟点了哪里、卡在哪、问了什么
- **不要在旁边解释**——她卡住的地方才是真问题

## 六、值得保留的（这是事实，不是恭维）

- **天文数据是真的**（VSOP87 + 真实日月食目录）。市面上 90% 的科普动画是美术糊弄的，这个底子值钱
- 奔月任务的电影化叙事方向正确
- 工程规范（测试覆盖、构建流程、双产物）远超个人兴趣项目的平均水平

## 七、具体风险

- **语音朗读**依赖系统中文语音包。幼儿园电脑大概率没有中文 TTS，会静默失败——**开发者以为是功能，老师会以为是坏的**
- **背景音乐**是程序化生成的。"能响"和"好听"差很远，教室音箱里放可能很尴尬。**建议先删掉**，等真的听过再说
- 736KB 单文件在老教室电脑上加载慢，而 `#boot-screen` 只有一句"正在加载宇宙…"，老师会以为卡死了

## 八、必须先回答的问题

**这个项目到底是什么？**

| | 选择 | 对应做法 |
|---|---|---|
| **A** | 一次性礼物，给这一个老师用 | 现在就交付，别再改，去收反馈 |
| **B** | 想做成正经产品 | 砍掉大半功能，围绕"幼儿园/小学低年级天文课"重做，做成课件而不是工具 |
| **C** | 自己玩的技术练手 | 随便做，开心就好 |

**这三条路要做的事完全不同，而现在是拿 A 的投入混着 B 的野心。**

先回答这个，再谈下一步做什么。
