# 奔月模块维护指南（`src/modules/lunar-mission.js`）

一个**独立的电影模块**：自己的 `THREE.Scene`、自己的比例尺、自己的一套相机运镜，
不复用全景场景。主循环在任务激活时渲染 `lunarMission.render()` 而不是 `current.render()`，
相机/渲染器/HUD 弹窗复用全局。

## 1. 电影比例尺（非天文单位）

```js
const RE=1.0    // 地球半径
const RM=0.27   // 月球半径
const MD=15.0   // 地月距离
const PARK=1.35 // 停泊轨道半径
const LUNAR_R=0.6  // 环月轨道半径
```

发射点在 **+Y 极**（`this._site`），月球在 **+X**，所有轨道都在 **XY 平面**（`z=0`）。
`1 单位 ≈ 308 m`（火箭全长 0.185 ≈ 57 m）。注意：这是"示意图比例"，不是真实比例，
火箭相对地球被放大了几个数量级——**任何"看着不对"的尺度问题，先回到这里对齐预期**。

## 2. 阶段机

```js
const ORDER=['COUNTDOWN','IGNITION','LIFTOFF','SPHERE','STAGE_SEP','EARTH_ORBIT',
             'TRANSFER','LOI','LUNAR_ORBIT','LANDING','LANDED'];
const DUR={ ... }          // 每阶段秒数（总时长 ≈68s）
```

- `_setPhase(p)` → 重置 `pt`、清 `_camEaseT`、调用 `_enterPhase(p)`（放置物体、开关可见性、生成烟云）。
- `update(dt)` 每帧累加 `pt`，`k=pt/DUR[phase]`，`k>=1` 时进入下一阶段。
- 文案在 `PHASE_NAME/PHASE_NAME_KID/WHY/WHY_KID`。

**加一个新阶段**：ORDER/DUR/文案四处都要加；`_enterPhase` 里写进入时的状态；
`update()` 的 switch 里写每帧的物体位置；`_camDesired()` 里写机位。
如果它影响环境（比如离开地球），还要在 `_updateEnv()` 里加可见性/淡出规则。

## 3. 物体与坐标约定

| 对象 | 说明 |
| --- | --- |
| `this.rocket` | 运载火箭组。**原点在整箭底部**；`userData.stage1/stage2` 是两级子组，`userData.stageSplit` 是一级长度 |
| `this.boosters` | 4 台助推器，**各自是子组**（`userData.dir` 是外法线方向，`userData.orb` 是距轴心距离），可独立翻滚 |
| `this.change` | 嫦娥（服务舱+着陆器）。`userData.lander` 是着陆器子组 |
| `this.plumeR / this.plumeC` | 尾焰。R 挂在一级（大气层内实心橙白焰），C 挂在**着陆器下降发动机**（真空淡蓝白加色焰） |
| `this.steam / this.burst` | 发射烟云 / 分离白烟，都是 Points 粒子池（`userData.parts`），有上限，靠 `_emit*` 复用 |
| `this.siteGroup` | 发射场（大地/海/道路/发射台/塔架/厂房/储罐/围栏/灯杆/树林） |
| `this.earthGroup / this.moonGroup / this.lunarPatch` | 地球(球+云+大气) / 月球 / 着陆点近景球冠 |

轨道数学：`_park/ _transfer/ _lunar/ _tangent*`，转移用 `_transferR(nu)`（椭圆）
和 `_nuFromM()`（平近点角→真近点角，**转移段必须用它**，否则违反开普勒第二定律，
速度箭头会和实际运动矛盾，相机也追不上）。

## 4. 相机导演

`_camDesired()` 返回 `{pos,tgt,up}`，按阶段给机位；`_updateCamera(dt)` 做平滑：

```js
this._camEaseT += dt;
const tau = this._camEaseT < 1.1 ? 0.42 : 0.16;   // 阶段切换后 1.1s 内放慢（转场从容）
this._cam.pos.lerp(d.pos, min(1, dt/tau));
this._cam.tgt.lerp(d.tgt, min(1, dt*18));         // 注视点几乎实时：否则快目标会被甩出画面
```

- 竖屏（宽高比 <1.02）会自动把机位沿视线后退，避免主体被裁。
- `EARTH_ORBIT` 会开放用户拖动：`controls.enabled=true`、`minDistance/maxDistance` 改成 0.5/6，
  离开时恢复。QA 截图必须先关掉它，否则相机会被 OrbitControls 拉回去。
- 绕地球机位用**轨道局部坐标系**（径向外 + 轨道面切向）；绕月机位用**月心→卫星**方向，
  这样天体恒定留在主体背后。

## 5. 环境（`_updateEnv`）

每帧统一处理：天空不透明度、星空、地球/月球的出现时机、发射场淡出、大气雾、**阴影相机范围**。

- 雾：地面段 `near=1.2 / far=16`；升空后推远。**`near` 必须小于 `far`**——
  否则 three 的 `smoothstep` 会饱和成 1，整幅画面被雾色糊掉（踩过一次）。
- 地球**不做透明度淡入**（透明期在黑色背景上是一颗黑球），改成"地面淡出、露出已点亮的地球"。
- 阴影：`_shadowFit(center,r,far)` 按阶段把平行光的正交阴影相机对到发射场/地球/月球。

## 6. 子事件（不是独立阶段）

| 事件 | 触发 | 实现 |
| --- | --- | --- |
| 助推器分离 | `STAGE_SEP` 进入时 | 4 台各自外飘翻滚 + `_spawnBurst` 白烟 |
| 一级分离 | `EARTH_ORBIT` k∈[0.02,0.18] | `_updateStaging` / `_applyStaging` |
| 抛整流罩 | `EARTH_ORBIT` k∈[0.26,0.56] | 两瓣对开、落后、淡出；铰链在根部 |
| 着陆器分离下降 | `LANDING` 进入时 | `_detachLander`：按当前轨道点**正下方**定落点（径向垂直下降） |

这些都用"按 `k` 计算目标值、只增不减"的写法，**不要用独立的计时器**——
否则 QA 定格（`dt=0`）时状态不对，截图会和真实流程不一致。

## 7. 渲染器设置与还原

任务开始时保存并设置 `toneMapping=ACESFilmic / exposure / shadowMap.enabled / type`，
结束时在 `_teardown` 里还原（`verify-lunar.mjs` 有断言）。新增全局渲染状态时记得一起存取。

## 8. 自检

见 `docs/视觉自检台.md`。常用：

```bash
npm run build:offline && npm run test:vision   # 11 阶段 × 7 机位接触表
npm run test:run                              # 整片连拍 + 转场跳变检测 + 各阶段真实耗时
npm run test:strip -- LANDING 8               # 单阶段胶片（看节奏）
npm run test:perf                             # 真机帧率 / draw call
node scripts/verify-lunar.mjs                 # 端到端验收（含渲染设置还原、雾参数）
```
