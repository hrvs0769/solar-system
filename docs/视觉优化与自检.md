# 视觉打磨与截图自检记录

> 说明：本轮通过 puppeteer 无头连接系统 Chrome，对应用进行了**真实浏览器截图 + 逐像素诊断**，发现并修复了 3 个影响画面/启动的问题，并完成一轮 UI 视觉打磨。执行模型具备视觉能力，以下为依据截图自我审查的结论。

## 一、修复的 3 个关键 Bug

### 1. 启动报错「Argument must be a Date object, an AstroTime object…」
- **根因**：`src/config.js` 的 `BODIES` 缺少 `periodDays`（公转周期）字段，`createOrbitLine` 采样 `jd = jd0 + periodDays*(i/N)` 得到 `NaN` → `jdToDate(NaN)` 生成无效日期 → astronomy-engine 抛错。
- **修复**：为每个行星补充正确的 `periodDays`；并在 `createOrbitLine` 增加非有限周期兜底（防复发）。

### 2. 背景整屏泛灰/米色（不是深太空）
- **根因**：`orbit-view` 渲染时执行 `root.position = -camera.position`，与 three 的相机视图矩阵**重复平移**（相当于对世界减了 2× 相机位置），导致星场与天体错位；同时太阳日冕**精灵(Sprite)**在此渲染路径下被错误放大，以叠加方式把整屏垫成米色。
- **修复**：移除重复的 root 平移，改为星场始终以相机为中心（远景背景）；移除精灵日冕，改用**菲涅尔加法壳**做柔和日冕辉光（BackSide，小半径、低不透明、偏橙）。

### 3. 行星名称标签不显示
- **根因**：`CSS2DRenderer` 未调用 `setSize()`，标签容器尺寸为 0，投影定位错位（标签被堆到 (0,-8)）。
- **修复**：创建时即 `setSize(window)`，并在窗口 resize 时同步。

## 三、视觉参数调整（相对《详细设计文档》的偏差）

| 项 | 文档初值 | 落地值 | 原因 |
|---|---|---|---|
| 行星视觉放大 | 真实 ×300 | **×1200** | ×300 下全景依然小到不可见 |
| 太阳视觉放大 | ×10 | **×60**（+日冕辉光） | ×10 过于渺小 |
| 月地示意轨道/半径 | 0.04 / 0.0016 AU | **0.16 / 0.02 AU** | 需大于地球视觉半径，月球才可见 |
| 默认相机 | 26 AU | **[3.2,2.6,3.2]（≈5.2 AU）** | 更近的英雄机位，太阳+内行星清晰 |
| 星场 | 彩色 | **低饱和偏白、更小更淡** | 去除廉价绿/彩色星 |
| 日冕 | 3 层精灵 | **菲涅尔加法壳** | 精灵在该渲染路径放大导致全屏泛灰 |

- 全部科普文案仍标记 `reviewStatus:'pending'`，需老师审校。
- 说明：真实距离下，全景中内行星为「轨道线上带名称的小点」属预期（体现宇宙真实尺度）；点击任意行星即自动对准近景。
